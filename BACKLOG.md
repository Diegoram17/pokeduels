# Backlog: Pokémon Duels

> Estado del repo al generar este backlog: el motor de combate puro (`frontend/src/engine/`) y
> las 7 pantallas del frontend ya existen, validados con TDD, pero corren sobre un **mock state**
> en `localStorage` (`useMockState`). No existe todavía carpeta `backend/`: no hay servidor
> Express/Socket.IO ni Postgres. Este backlog cubre lo que falta para llegar al sistema real
> descrito en `TECH-DESIGN.md` — no repite el motor ni las pantallas ya construidos.
>
> Nota: existió una carpeta `poke-duel-engine/` (motor de combate copiado de otro proyecto) que
> resultó estar rota y sin usar en ningún lado del repo (`package.json` con JSON inválido,
> `duel.js` sin las funciones que su propio test suite esperaba) — se eliminó del repo. La única
> implementación real y vigente del motor es `frontend/src/engine/`.

## Cómo usar este backlog

Cada ítem es una spec independiente. Al implementarlo, arrancá un ciclo de Spec-Driven
Development (`sdd-new` o el flujo equivalente de tu harness) usando este ítem como el
"change" — no el proyecto completo. Si la columna "Contexto extra requerido" tiene algo,
compartilo como contexto al generar la spec de ese ítem.
